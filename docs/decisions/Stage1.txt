ЕТАП 1. ФУНДАМЕНТ VALUE-ТИПІВ ПРОЄКТУ
============================================================

1. ЗАГАЛЬНА МЕТА

Мета цього етапу — створити фундамент value-типів проєкту. Замість того щоб використовувати примітивні типи (int, uint32_t, std::vector<std::vector<T>>) у різних частинах коду, потрібно створити суворі, оптимізовані та типобезпечні обгортки.

Основні завдання:

1. Типобезпека (Id<Tag>)
   Запобігти помилкам на етапі компіляції. Якщо функція очікує ID будівлі, передати їй ID агента буде неможливо, навіть якщо обидва типи зберігаються як uint32_t.

2. Продуктивність і неперервність пам'яті (Grid<T>)
   std::vector<std::vector<T>> зберігає рядки в окремих ділянках пам'яті. Це може погіршувати локальність даних і збільшувати кількість промахів кешу процесора. Grid<T> має зберігати двовимірну сітку в одному суцільному масиві std::vector<StorageType>, використовуючи формулу:
   index = y * width + x

3. Обхід проблем std::vector<bool>
   std::vector<bool> пакує значення в біти та використовує проксі-об'єкти замість звичайних посилань bool&. Це ускладнює роботу з елементами й може створювати проблеми під час паралельного запису. Grid<bool> має використовувати uint8_t як тип зберігання.

4. Детермінізм симуляції (Rng)
   Симуляція має бути відтворюваною для налагодження, реплеїв і мережевої синхронізації. Rng має дозволяти створювати окремий потік випадкових чисел для конкретного агента в конкретному такті на основі параметрів:
   (seed, tick, agent_id)

3. ПІДЗАДАЧА 1. РЕАЛІЗАЦІЯ Id<Tag>

Файл: util/Id.hpp

Що потрібно зробити:

1. Створити шаблонний клас:
   template <typename Tag, typename Underlying = std::uint32_t>
   class Id

2. Конструктор:
   explicit constexpr Id(Underlying value) noexcept

   Конструктор має бути explicit, щоб заборонити неявне створення, наприклад:
   Id id = 5;

3. Невалідний стан:
   static constexpr Id invalid() noexcept

   Метод повертає максимальне значення типу Underlying.

4. Перевірка валідності:
   [[nodiscard]] constexpr bool is_valid() const noexcept

   Метод перевіряє, чи не дорівнює поточне значення значенню invalid().

5. Оператори порівняння:
   - operator==
   - operator!=
   - operator<
   - operator>

   За умови використання C++20 можна реалізувати operator<=>.

6. Метод доступу до значення:
   [[nodiscard]] constexpr Underlying value() const noexcept

7. Хешування:
   Спеціалізувати std::hash<Id<Tag, Underlying>> у просторі імен std, щоб Id можна було використовувати як ключ у std::unordered_map.

8. Rule of Zero:
   Не потрібно вручну реалізовувати копіювання, переміщення або деструктор. Компілятор може згенерувати їх автоматично.

Перевірочний тест:
Файл: tests/unit/util_id_test.cpp

Потрібно перевірити:

- Типобезпеку ID різних тегів за допомогою static_assert:
  static_assert(!std::is_convertible_v<Id<TagA>, Id<TagB>>);

- Роботу is_valid() та invalid().
- Вставлення та пошук Id у контейнері:
  std::unordered_map<Id<AgentTag>, std::string>


4. ПІДЗАДАЧА 2. РЕАЛІЗАЦІЯ Cell ТА Grid<T>

Файл: util/Grid.hpp

4.1. Структура Cell

Потрібно реалізувати:

- Поля координат:
  std::int32_t x{0};
  std::int32_t y{0};

- Оператори:
  operator==
  operator!=
  operator+
  operator-

- Хешування:
  Реалізувати якісну функцію хешування для std::hash<Cell>. Наприклад, використати алгоритм hash_combine з бітовими зсувами, а не просту операцію x ^ y.

4.2. Шаблон Grid<T>

Тип зберігання:

using StorageType =
    std::conditional_t<std::is_same_v<T, bool>, std::uint8_t, T>;

Дані потрібно зберігати в одному суцільному масиві:
std::vector<StorageType>

Конструктор:

Grid(std::size_t width, std::size_t height,
     const T& default_value = T{});

Розміри та межі:

- [[nodiscard]] std::size_t width() const noexcept
- [[nodiscard]] std::size_t height() const noexcept
- [[nodiscard]] std::size_t size() const noexcept
- [[nodiscard]] bool in_bounds(Cell cell) const noexcept

Метод in_bounds() має перевіряти, що x та y не від'ємні й перебувають у межах сітки. Перед перетворенням координат на std::size_t потрібно перевіряти їхню невід'ємність.

Перетворення координат на індекс:

Реалізувати приватний метод:
std::size_t to_index(Cell cell) const

Формула індексу:
index = y * width + x

Під час перетворення координат використовувати static_cast<std::size_t>, щоб уникати попереджень компілятора -Wconversion та -Wsign-compare.

Доступ до елементів:

1. Швидкий доступ:
   - operator[](Cell cell)
   - operator()(std::int32_t x, std::int32_t y)

   У Debug-збірці потрібно перевіряти межі через assert(in_bounds(cell)). У Release-збірці перевірки через assert не виконуються.

2. Безпечний доступ:
   - at(Cell cell)
   - try_get(Cell cell)

   Метод at() має перевіряти межі й викидати std::out_of_range, якщо координати виходять за межі сітки.

   Метод try_get() може повертати T* або std::optional — потрібно вибрати один варіант і дотримуватися його послідовно.

Особливість Grid<bool>:

Оскільки для bool використовується uint8_t, потрібно забезпечити коректний доступ до значення як до bool. Зокрема, слід продумати типи посилань і покажчиків, які повертають operator[], at() та try_get(), адже елемент у сховищі фактично має тип uint8_t, а не bool.

Семантика переміщення:

Після std::move(grid) початкова сітка має залишатися в коректному порожньому стані:
- width() == 0
- height() == 0

Перевірочний тест:
Файл: tests/unit/util_grid_test.cpp

Потрібно перевірити:

- Розміри сітки.
- Запис і зчитування елементів через Cell.
- Роботу in_bounds().
- Виняток std::out_of_range під час виходу за межі в at().
- Копіювання сітки.
- Переміщення сітки та стан початкового об'єкта після переміщення.
- Grid<bool>: запис і зчитування значень.
- Можливість отримати посилання або покажчик на елемент Grid<bool> відповідно до обраного API.


5. ПІДЗАДАЧА 3. РЕАЛІЗАЦІЯ Rng

Файл: util/Rng.hpp

Що потрібно зробити:

1. Створити клас Rng із приватним полем:
   std::mt19937_64 engine_;

2. Конструктор:
   explicit Rng(std::uint64_t seed);

3. Фабричний метод для створення окремого потоку:
   [[nodiscard]] static Rng for_agent(
       std::uint64_t seed,
       std::uint64_t tick,
       std::uint64_t agent_id) noexcept;

   Метод має об'єднувати seed, tick та agent_id у нове значення seed, а потім повертати Rng(combined_seed).

   Для комбінування можна використати надійний алгоритм змішування бітів. Простого XOR може бути недостатньо, оскільки різні набори параметрів можуть давати однаковий результат.

4. Допоміжні методи:

   - [[nodiscard]] std::uint64_t next_u64()
   - [[nodiscard]] std::int32_t range(std::int32_t min, std::int32_t max)
   - [[nodiscard]] double uniform()
   - [[nodiscard]] bool chance(double probability)

Призначення методів:

- next_u64() повертає наступне 64-бітове випадкове число.
- range(min, max) генерує ціле число в заданому діапазоні за допомогою std::uniform_int_distribution<std::int32_t>.
- uniform() генерує дійсне число в діапазоні [0.0, 1.0).
- chance(probability) повертає true, якщо випадкове число менше за probability.

Для chance() бажано визначити поведінку граничних значень:
- probability <= 0.0: завжди false;
- probability >= 1.0: завжди true;
- значення між 0.0 та 1.0: порівняння з uniform().

Також потрібно визначити поведінку для NaN, якщо він може передаватися як probability.

Перевірочний тест:
Файл: tests/unit/util_rng_test.cpp

Потрібно перевірити:

1. Детермінованість:
   Два об'єкти Rng з однаковим seed мають видавати однакову послідовність значень range().

2. Ізоляцію потоків:
   Rng::for_agent(seed, tick, 1) та Rng::for_agent(seed, tick, 2) мають видавати різні послідовності чисел для вибраних тестових параметрів.

3. Статистичну рівномірність:
   Згенерувати 10 000 значень за допомогою chance(0.5) та перевірити, що кількість true перебуває в заданих межах, наприклад від 4500 до 5500.

Примітка: статистичний тест не доводить математичної рівномірності генератора, а лише допомагає виявити очевидні помилки реалізації.

7. ЗАГАЛЬНИЙ КРИТЕРІЙ ГОТОВНОСТІ

Етап 1 вважається завершеним, якщо:

- Id<Tag> забезпечує типобезпеку, підтримує invalid(), is_valid(), порівняння та хешування.
- Cell підтримує потрібні операції та хешування.
- Grid<T> зберігає дані в суцільному масиві й коректно перевіряє межі через безпечний API.
- Grid<bool> використовує uint8_t замість std::vector<bool> і має чітко визначену семантику доступу.
- Rng забезпечує відтворюваність і створення окремих потоків для агентів та тактів.
- Усі три набори юніт-тестів додано до системи збірки й вони проходять успішно.
